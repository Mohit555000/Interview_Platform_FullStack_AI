🎙️ I built an AI-powered Mock Interview Platform — and here's everything I learned building it.
The best way to crack an interview is practice. Not theory. Not LeetCode. Actually sitting in front of someone and answering questions out loud, under pressure, in real time.
But getting that practice is expensive. Seniors are busy. Paid platforms charge ₹500–₹2000 per session. Peer practice gives you no real feedback. And talking to yourself tells you nothing about whether your answer was actually correct.
So I built InterviewAI — a fully voice-based AI interview platform that gives anyone access to unlimited, personalized mock interviews. Free. Anytime. With detailed feedback.

🔍 How It Works
Upload your resume and job description. Select your interview duration. That's it.
The AI greets you by voice and starts the interview immediately — no scheduling, no waiting, just like a real interviewer.
✅ Adaptive Questions — every question is generated by analyzing your resume, the JD, and your previous answers together. Answer well and it goes deeper. Struggle and it revisits the concept from an easier angle.
✅ 4-Dimension Scoring — every answer is scored on Technical Accuracy, Clarity, Confidence, and Problem-Solving. No more vague feedback like "you need to improve."
✅ Role-Specific Interviewer — the AI reads the JD and generates an interviewer persona dynamically. A Senior Data Scientist for data roles. A Frontend Engineering Lead for React positions. The tone and questions shift to match the actual role.
✅ Comprehensive Report — when the interview ends, you get a full written report covering your strengths, exact weak areas, concrete study recommendations, and an overall rating out of 5.

⚙️ The Tech Stack

Frontend — React + Vite
Backend — FastAPI + LangChain + LangGraph
LLM — OpenAI GPT-4o-mini for question generation, evaluation, and reports
TTS — OpenAI gpt-4o-mini-tts with fable voice for consistent AI speech
STT — Google Speech Recognition via Python's speech_recognition library
Vector DB — Qdrant Cloud for semantic retrieval of JD topics
Graph DB — Neo4j Aura to store candidate skills, scores, and weaknesses as a knowledge graph
Deployment — Vercel (frontend) + Render (backend)

Multi-provider LLM support included — users can bring their own OpenAI, Anthropic, or Gemini key.

🧠 The Hard Technical Problems I Solved
The biggest challenge wasn't the AI. It was the gap between what the user said and what the system understood.
Problem 1 — STT is messy. "Avent loop" gets transcribed instead of "event loop." A correct answer gets penalized because the microphone wasn't perfect.
Problem 2 — Users describe concepts without naming them. A candidate explains exactly how a database index works — comparing it to the index at the back of a book — but never says the word "index." The evaluator sees no keywords and scores it lower than it deserves.
Problem 3 — Single-query retrieval misses related topics. The JD says "state management" but the covered topics say "React hooks." One search query misses the connection entirely.

💡 Four Techniques I Implemented to Solve These
1. Multi-Query Generation — instead of one search query, the system generates 3 variations: a gap query (what hasn't been asked), a prerequisite query (what basics come before the next topic), and a progression query (what harder topic comes next if the candidate is doing well).
2. Sub-Query Decomposition — complex topics like "how does a browser load a page" get broken into atomic pieces: DNS lookup, HTTP request cycle, browser rendering. Each piece retrieves better results from the vector database.
3. Reciprocal Rank Fusion (RRF) Reranking — all parallel search results are merged using a voting system. Topics that rank highly across multiple searches score higher than topics only one search liked. The most consistently relevant topic wins.
4. Contextual Answer Normalization — before evaluation, the user's spoken answer passes through a normalization layer. It uses the question as context to fix STT errors, map informal descriptions to proper technical terms, and make implied knowledge explicit — while never adding knowledge the candidate didn't actually have. The evaluator judges understanding, not vocabulary.
